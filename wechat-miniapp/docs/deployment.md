# 部署与上线验收

当前生产架构只有一条数据链路：微信小程序通过 HTTPS 访问 SaaS storefront API。小程序不连接第二套数据库、云函数或支付实现；订单、库存、支付、退款、履约和权限事实全部由 SaaS 服务端负责。

## 1. 模式与环境

`miniprogram/config/runtime.js` 显式选择 `demo` 或 `production`。演示模式只使用本地演示数据，不发起真实收款；生产模式必须同时配置 HTTPS `apiBaseUrl` 和公开 AppID，缺失时 fail-closed。AppSecret、支付密钥、证书和数据库凭据只能保存在 SaaS 服务端渠道账号中。

正式发布前，在 SaaS 管理后台完成：

1. 为租户开通餐饮或电商能力，并创建对应履约地点、商品、SKU 和库存。
2. 创建并配置 `wechat_miniapp` 渠道账号，保存 AppID/AppSecret。
3. 在 storefront 绑定中把渠道账号绑定到允许的业务类型和履约地点。
4. 将 SaaS HTTPS 域名加入微信小程序的 request、uploadFile、downloadFile 和业务域名配置。
5. 使用正式 AppID 验证登录、目录、购物车、地址、订单查询、支付和退款。

同一 AppID/session/cart 的业务范围由 SaaS session 授权决定，客户端不能通过参数伪装业务类型。若一个小程序同时经营餐饮和电商，后端必须返回两个明确授权的业务上下文并隔离各自购物车、订单和履约地点；未授权业务必须隐藏并拒绝请求。

## 2. 发布包检查

微信开发者工具私有配置 `project.private.config.json` 不提交 Git。发布前确认：

- `project.config.json` 的 AppID 与渠道账号一致。
- `runtime.js` 的 API 地址为 HTTPS，不能包含密钥。
- 生产页面只使用 `services/http.js` 的 SaaS 请求，不调用本地演示数据作为生产事实。
- `npm run verify` 和 `npm test` 通过；有条件时再执行微信开发者工具的离线 WXML/WXSS 编译。
- 真机检查键盘遮挡、图片、规格、地址、订单状态和错误提示。

## 3. SaaS 生产准入

在以下条件完成前，只能使用演示模式或由 SaaS 明确返回“支付渠道尚未接入”，不能把本地订单标记为已支付：

1. SaaS PostgreSQL 迁移完成，租户、商业能力、微信渠道账号和 storefront 绑定通过隔离检查。
2. 正式 AppID 的微信登录、session、目录、购物车、地址快照、订单列表和退款申请联调成功。
3. SaaS 接入真实微信支付下单、回调验签/解密、主动查单、超时和重启恢复；支付金额只能来自服务端订单快照。
4. SaaS 接入真实退款申请、退款回调和幂等重试；退款确认前订单、库存和履约状态不能提前结转。
5. 商家履约 worker、订阅通知、日志告警、备份恢复和失败补偿完成演练。
6. 使用低额真实订单完成支付、履约、退款和重复请求验收。

## 4. 现阶段明确边界

当前 storefront 若未提供配送区域、跑腿费计价、优惠券、助力或商家管理接口，小程序必须显示不可用并拒绝写入，不能用缓存或旧数据补齐服务端事实。生产餐饮只能开放 SaaS 已支持的履约方式；零售订单必须使用服务端认可的快递地址和费用。

本地回归只验证客户端协议、状态、幂等和页面逻辑，不能替代真实 SaaS、微信支付网关、真机布局或现场履约验收。
