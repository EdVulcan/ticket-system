# v1.0 验收用例

- 商品下架后首页不应允许加购；商品库存为 0 时展示售罄。
- 生产订单按所选配送区域的起送价校验，不得用门店展示默认值阻挡另一个零起送价区域；最终以服务端核算为准。
- 商品规格、数量和备注会保存到订单快照。
- 结算页优惠券只抵扣商品金额，配送费独立计算。
- 提交订单后购物车清空，订单列表和订单详情出现新订单。
- 商品、规格、库存和订单处理由 SaaS 管理后台验收，消费者小程序不提供店主工作台。
- 店主修改商品上下架、库存和店铺公告后，顾客端重新进入页面能看到结果。
- 助力任务只能完成一次，成功后双方优惠券显示在“我的优惠券”。
- 地址增删改和默认地址选择可以在结算页生效。
- 编辑普通快递地址时即使请求省略 `addressType` 也不能被改写为校园地址；校园和快递默认地址相互独立。
- 混合购物车会按外卖/冷吃拆分关联订单，各订单只绑定正确地址、起购规则和优惠券。
- 冷吃订单只允许填写快递单号后发货，用户可确认收货；外卖订单保留人工跑腿履约状态。
- 启用活动引用的优惠券模板换版会自动绑定新版本，停用仍被启用活动引用的模板会被拒绝，旧助力任务仍可发放旧券。
- 商家订阅授权入口只向有订单权限的店员显示；普通未付款订单不提前发送新订单接单提醒，支付成功后最多按实际支付转换触发一次。
- 订单历史显示商品快照，不因当前商品库存或名称变化而改变。

## 可重复执行的本地回归

`npm run verify`：JS语法、JSON、注册页面文件、WXML标签与事件、共享核心副本一致性。

`npm test`：支付/取消/退款并发和幂等、SDK随机串/退款索引字段、RSA验签和AES-GCM通知、金额和身份拒绝、失败退款轮转、异常退款状态及新单号CAS、商品库存/规格/权限、地址默认指针、助力任务、生产缓存和客户端支付恢复。

这些是客户端协议和页面逻辑回归，不能证明真实 SaaS 隔离、索引、支付网关、回调或界面布局已通过。真实环境验收清单见 `deployment.md`，仍待执行。
