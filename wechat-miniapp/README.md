# 琑遇·二两兔｜微信商业小程序

这是餐饮与通用电商小程序客户端，唯一生产数据源是本项目 SaaS 的 HTTPS storefront API。小程序不承载订单、库存、支付、退款或商家权限事实，也不包含服务端密钥。

原生微信小程序通过 SaaS API 服务成都门店“琑遇·二两兔”。同一商业域支持餐饮外卖与通用电商履约；门店自行联系跑腿，顾客支付服务端核算的费用。

## 当前实现

- 顾客：餐饮/零售目录、分类、图片、规格、双履约购物车、地址、订单备注、微信支付、支付恢复查单、订单状态和再来一单。
- 零售：普通快递地址、快递费/包邮门槛、发货单号、待发货/待收货/已完成状态。
- 助力：演示模式提供本地交互；生产入口在 SaaS 接口开放前明确不可用，不写本地优惠券事实。
- 商家：顾客订单、支付和退款由 SaaS 负责；商家商品、配送、活动、优惠券和统计入口在 SaaS 接口未开放时显示不可用并禁止写入。
- 通知：订单确认支付后，SaaS 按已授权的订阅消息配置尝试通知有订单权限的店员。
- 安全：微信会话、租户/渠道归属、服务端金额核算、订单快照和退款状态均以 SaaS 为准；客户端不伪造支付成功。

当前仓库的 `miniprogram/config/runtime.js` 记录了 SaaS HTTPS 地址和公开 AppID。正式发布前仍需完成租户渠道绑定、真实登录、微信支付/退款回调、履约通知和真机验收；这些条件未满足时不得视为生产上线完成。

## 本地检查

Node.js 20+，不需要安装项目依赖即可运行静态检查和回归：

```text
npm run verify
npm test
```

`verify` 检查 JavaScript/JSON、已注册页面文件、WXML 标签和事件，并拒绝页面直接调用 `wx.cloud`。`test` 是客户端协议、状态和页面逻辑回归，不是真实 SaaS 网络、支付网关或微信界面渲染测试。

有微信开发者工具编译器时，可执行离线编译（只编译，不启动 IDE、不上传、不发布）：

```text
node scripts/compile-wechat.js --compiler-dir "微信开发者工具安装目录/resources/app.asar.unpacked/node_modules/wcc-exec"
```

## 部署边界

详见 [部署说明](docs/deployment.md)、[接口约定](docs/api-contracts.md) 和 [审计记录](docs/audit-2026-09-07.md)。

正式包只能使用 SaaS storefront API；AppSecret、支付密钥、证书和数据库凭据只保存在 SaaS 服务端渠道配置中。微信开发者工具的本机私有配置不提交到 Git。

金额统一使用整数“分”。已支付订单保留订单时快照；退款、库存和履约状态由服务端幂等协调。
