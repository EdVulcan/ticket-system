# 琑遇·二两兔｜校园餐饮外卖小程序

> 当前生产方向已切换为本 SaaS 的 HTTPS storefront API。CloudBase 云函数、数据库和支付实现仅保留作历史参考，不是生产商品、库存、订单、支付或退款数据源。

原生微信小程序，通过 SaaS HTTPS API 服务成都门店“琑遇·二两兔”。同一商业域支持校园外卖与通用电商履约；门店自行联系跑腿，顾客支付外卖跑腿费；没有骑手平台。

## 当前实现

- 顾客：外卖/冷吃双频道、分类、图片、口味/份量规格、双履约购物车、校园/普通快递地址、订单备注、微信支付、支付恢复查单、订单状态和再来一单。生产 SaaS 尚未提供优惠券、助力、配送区域/跑腿费计价接口，生产餐饮暂只开放门店自提；演示模式保留校园配送流程。
- 冷吃：成都发货、快递费与包邮门槛、冷吃起购金额、快递公司和单号、待发货/待收货/已完成状态。
- 助力：演示模式提供完整交互；生产入口在 SaaS 助力接口接入前明确不可用，不写本地优惠券事实。
- 门店：生产顾客订单/支付/退款边界已接 SaaS；商家订单履约、商品、配送区域、活动、优惠券和统计接口尚未接入时统一显示暂未开放并禁用写操作，演示模式保留本地工作台。
- 通知：订单确认支付后尝试向有 `ORDER_MANAGE` 权限且已授权订阅消息的店员发送新订单提醒；未配置模板时订单流程不受影响。
- 支付：服务端核算金额/库存/券；共享状态机；取消前核实并关单；重复回调幂等；退款定时核对；取消后到账自动进入同单号全额退款。
- 安全：OpenID归属、员工权限、服务端事务、订单字段脱敏、生产/演示缓存隔离。0元全券订单单独记账，不伪造微信交易。

默认仍为 **demo 演示模式，不能收款**。生产客户端已接线到 SaaS storefront 的目录、购物车、订单、支付创建/查单和退款申请接口，但尚未配置正式 API 地址、后台发布绑定、真实微信支付/退款回调、履约 worker 或真机验收，不能视为已经上线。正式配置缺失时仍 fail-closed，不会伪造支付成功。

## 本地使用

微信开发者工具打开根目录，默认保持 `miniprogram/config/runtime.js` 中 `deploymentMode: 'demo'`。正式包只能由发布配置注入 `production`、SaaS HTTPS `apiBaseUrl` 和正式 AppID；不要把 AppSecret 或支付密钥写入小程序。演示订单数据只存在本地，生产商品、库存、地址、订单和售后必须来自 SaaS API。

Node.js 20+，回归检查不需要安装项目依赖：

```text
npm run build:cloud
npm run verify
npm test
```

`verify` 检查JS/JSON、19个注册页面文件、WXML标签/事件和共享代码一致性，并拒绝注册页面调用 `wx.cloud`；`test` 是带事务模拟、支付协议/验签及页面逻辑的自动化回归，不是真实 SaaS 网络、支付网关或微信界面渲染测试。

本机已使用微信开发者工具自带编译器通过19个注册页面WXML及23个WXSS文件的离线编译。可重复执行：

```text
node scripts/compile-wechat.js --compiler-dir "微信开发者工具安装目录/resources/app.asar.unpacked/node_modules/wcc-exec"
```

此命令只编译，不启动IDE、不上传、不发布；真机布局和设备接口仍待验收。

## 部署

详见 [部署说明](docs/deployment.md)、[接口约定](docs/api-contracts.md)、[审计记录](docs/audit-2026-09-07.md)。

正式支付仍需完成 SaaS 侧真实微信支付下单、回调验签/解密、退款回调和商户联调；完成前不得将 demo 包切换到 production。历史 `cloudPay` 资料见部署说明的存档章节，不能作为生产配置指引。

`cloud-shared/payment-core.js` 是支付逻辑唯一源文件。`npm run build:cloud` 将其打包到4个独立上传的云函数目录，避免跨云函数相对路径依赖。修改后先构建，再验证/部署。目录不是Git仓库，请另外做好版本备份。

金额统一使用整数“分”。已支付订单保留快照。退款默认不补库存、不返已使用券；若需补货，由有权限的店员明确操作。
