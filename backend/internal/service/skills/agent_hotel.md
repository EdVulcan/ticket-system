# 酒店住宿 Agent 能力

酒店是独立住宿履约域，不是景区票种，也不是 PMS。房型共享按入住日房量；房型价格计划日历维护供给价，独立酒店产品日历维护销售价，两者不能混用。

## 可以查询

- 酒店、房型、价格计划和独立酒店产品目录。
- 指定酒店、房型、入住日期范围的容量、预留、已售、剩余和关房状态。
- 房型价格计划的基础价与入住日覆盖价。
- 日历房酒店产品当前 revision 的销售价日历；预售房没有销售价日历。
- 酒景套餐住宿预订和预约权益摘要，以及现有售券、预约、入住、离店、未到店业务汇总。

查询结果只来自当前租户服务器事实。不得展示住客姓名、电话、证件、票码、内部数据库编号、外部凭据或推测的库存。

## 可以预览并在确认后执行

1. 按一个酒店、一个房型和明确的最多 93 天日期范围设置房量或关房状态。
2. 按一个酒店、一个房型、一个价格计划和明确日期范围设置或清除入住日覆盖价。
3. 按一个酒店、一个日历房产品和明确日期范围设置或清除销售价覆盖；预售房必须拒绝。
4. 对一个精确酒景套餐住宿预订登记“已入住”“已离店”或“未到店”。未到店必须填写原因。

每个写入先生成逐日/逐预订前后差异，明确显示目标和日期，再等待用户确认。服务端在确认时重新检查租户、酒店业态、权限、当前 revision、每日房量快照和预约状态；任何变化都要求重新预览。容量不能低于已预留加已售，关房不释放既有事实。

## 不开放

不创建或删除酒店/房型/价格计划/产品，不修改基础价、销售模式、房晚和预约规则，不上线/下线或发布渠道；不创建、取消、改期、退款、重试外部预约，不写小红书、携程、OTA、PMS、Webhook，不处理支付、结算、排房、房卡、押金、夜审、房务或住客档案。

不要把“预订状态”“预约权益状态”“支付状态”和“退款状态”混为一个字段。外部平台调用和资金事实必须由对应业务页面或持久任务处理。
