# 携程供应商订单直连接入说明

## 1. 定位

本项目以景区供应商身份直接接收携程订单，不使用“系统服务商代商户接入”模式。
实现依据为携程景点玩乐开放平台订单接口文档和供应商沙箱，不把 SDK 作为运行依赖。
SDK 仅在沙箱字段含义与公开文档不一致时用于比对示例。

官方订单文档：`https://open.trip.com/apiplatform/order.jsp`

## 2. 当前已实现

- 独立的携程渠道账号，每个景区租户分别保存自己的账号、签名密钥、AES 密钥和初始向量。
- 密钥使用系统实例密钥加密落库，管理端和查询接口均不回显明文。
- 官方签名顺序：`accountId + serviceName + requestTime + body + version + signKey`，结果取小写 MD5。
- AES-128-CBC、PKCS5/PKCS7 补位和官方 `a-p` 半字节编码；兼容旧示例中的 Base64 密文输入。
- 请求时间窗口、IP 白名单、每分钟限流、流水号幂等和“相同流水号不同正文”拒绝。
- `CreatePreOrder`：支持多订单项、商品 PLU 映射、出行人、库存预占和本地未支付订单创建。
- `PayPreOrder`：同步确认支付，复用本地出票链路，向携程返回数字码和二维码原始字符串。
- `CancelPreOrder`：释放未支付订单的库存和票权。
- `CancelOrder`：支持未核销订单的整单同步取消；当前明确拒绝部分退订，避免误退。
- `QueryOrder`：按携程订单号查询本地订单项、使用数量、取消数量和凭证状态。
- 请求和响应记录进入现有渠道请求日志；同批次重试返回完全相同的响应。
- 携程订单与本地订单只建立轻量协议关联，票、库存、核销和结算仍以现有领域模型为准。
- PostgreSQL 与 SQLite 均增加携程账号唯一性和跨租户、跨订单归属保护。

商家订单接口地址：

```text
https://<部署域名>/api/v1/integrations/ctrip/order
```

当前部署域名对应：

```text
https://ymsq.edvulcan.top/api/v1/integrations/ctrip/order
```

## 3. 管理端配置顺序

1. 进入“渠道连接”，新增类型为“携程”的渠道，测试阶段选择“测试环境”。
2. 填写携程沙箱“订单参数”中的接口账号、接口密钥、AES 加密密钥和 AES 初始向量。
3. 在“商品映射”中，把携程 PLU 对应到本景区已上架产品。
4. 将页面展示的商家接口地址填入携程沙箱。
5. 先完成预下单、支付、查询和取消的遍历测试，再申请切换正式参数。
6. 正式环境另行填写生产密钥，不能复用或复制测试密钥。

## 4. 尚需沙箱和真实条件

- 携程账号最终接口能力勾选和测试产品数据。
- 沙箱遍历测试及域名审核。
- 部分按份数、按出行人的退订规则和携程测试用例。
- `RefundOrder` 仅退款：该接口只在合同约定由商家处理对客售后时接入；未确认前继续由 VBooking 人工处理。
- 核销后向携程发送 `OrderConsumedNotice` 的目标地址、重试频率和真实响应验收。
- 携程账单样本与本系统核销收入、取消和退款事实的对账验收。
- 生产账号、生产密钥和携程提供的正式来源网络地址。

以上项目在真实沙箱通过前不标记为生产可用，也不使用模拟成功代替。
