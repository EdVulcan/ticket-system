# 携程供应商订单直连接入说明

## 1. 定位

本项目以景区供应商身份直接接收携程订单，不使用“系统服务商代商户接入”模式。
实现依据为携程景点玩乐开放平台订单接口文档、供应商沙箱邮件和官方 Go SDK。官方 SDK 当前以 ZIP 分发，模块名和示例代码不适合直接作为稳定生产依赖，因此项目实现了隔离的协议客户端，只保留签名、加密、服务名及价格库存模型；不引入演示代码、样例密钥和明文报文日志。

SDK 来源：`https://docs.c-ctrip.com/files/7/tour_order_connect/trip_sdk_golang.zip`

本次核验文件 SHA256：`3EB45B41A3F367481B0A4F536193629EFF9EB4AF80CE2EFD23DCBE88BE9DF9E5`

官方订单文档：`https://open.trip.com/apiplatform/order.jsp`

## 2. 当前已实现

- 独立的携程渠道账号，每个景区租户分别保存自己的账号、签名密钥、AES 密钥和初始向量。
- 密钥使用系统实例密钥加密落库，管理端和查询接口均不回显明文。
- 官方签名顺序：`accountId + serviceName + requestTime + body + version + signKey`，结果取小写 MD5；`body` 使用报文中传输的 AES 加密正文。订单入站与价格库存出站均遵守这一规则。
- AES-128-CBC、PKCS5/PKCS7 补位和官方 `a-p` 半字节编码；兼容旧示例中的 Base64 密文输入。
- 请求时间窗口、IP 白名单、每分钟限流、流水号幂等和“相同流水号不同正文”拒绝。
- `CreatePreOrder`：支持多订单项、商品 PLU 映射、出行人、库存预占和本地未支付订单创建。携程真实沙箱请求在该阶段不传 `itemId`，系统使用内部临时编号保存关联，查询未支付预订单时按协议返回 `itemId=0`。
- `PayPreOrder`：同步确认支付，接收携程在该阶段下发的正式 `itemId` 并原子回填订单项关联，复用本地出票链路，向携程返回数字码和二维码原始字符串。
- `CancelPreOrder`：释放未支付订单的库存和票权。
- `CancelOrder`：支持未核销订单的整单同步取消；当前明确拒绝部分退订，避免误退。
- `QueryOrder`：按携程订单号查询本地订单项、使用数量、取消数量和凭证状态。
- `OrderConsumedNotice`：闸机先在本系统完成本地核销事务，服务器随后写入持久通知任务并异步通知携程。外网超时不阻塞闸机开闸，失败按同一核销事实自动退避重试，只有携程返回成功才将任务标为完成。
- 请求和响应记录进入现有渠道请求日志；幂等键作用域为“渠道账号 + 服务名 + `sequenceId`”。携程会在 `CreatePreOrder` 和 `PayPreOrder` 复用同一 `sequenceId`，两个服务分别幂等；同一服务的同批次重试返回完全相同的响应。
- 携程订单与本地订单只建立轻量协议关联，票、库存、核销和结算仍以现有领域模型为准。
- PostgreSQL 增加携程账号唯一性和跨租户、跨订单归属保护。
- 携程商品映射独立保存该渠道的销售价和结算价，不覆盖景区产品原价，也不复用其他分销商报价。
- 支持按 1 至 90 天日期范围推送 `DatePriceModify` 和 `DateInventoryModify`。
- 价格、库存和核销通知先写入 PostgreSQL 持久任务，再由后台任务调用携程；进程重启后继续处理，失败自动退避，达到上限后在管理端显示原因。
- 沙箱和生产环境分开持久化；停用、重启和重新启用不会误切环境。沙箱使用携程邮件下发的 `ttdopen.ctrip.com` 固定地址。

商家订单接口地址：

```text
https://<部署域名>/api/v1/integrations/ctrip/order
```

当前部署域名对应：

```text
https://ymsq.edvulcan.top/api/v1/integrations/ctrip/order
```

## 3. 管理端配置顺序

1. 进入“渠道连接”，新增类型为“携程”的渠道，测试阶段选择“测试环境”。
2. 填写携程沙箱“订单参数”中的接口账号、接口密钥、AES 加密密钥和 AES 初始向量。
3. 在“商品映射”中，把携程 PLU 对应到本景区已上架产品，并填写携程合同约定的销售价和结算价。
4. 选择需要开放的日期范围，执行“同步价格库存”，确认价格和库存两条记录均为“已成功”。
5. 将页面展示的商家接口地址填入携程沙箱。
6. 先完成预下单、支付、查询、取消及价格库存的遍历测试，再申请切换正式参数。
7. 遍历测试中需要供应商主动核销时，可使用渠道操作中的“沙箱核销测试”并填写该测试单的供应商订单号；该入口仅接受启用中的携程测试环境订单，正式环境不会开放模拟核销。
8. 正式环境另行填写生产密钥，不能复用或复制测试密钥；生产价格库存地址需在上线前与携程再次确认。

## 4. 尚需沙箱和真实条件

- 携程账号最终接口能力勾选和测试产品数据。
- 订单遍历 18 项中 16 项已自动通过；剩余“消费后取消”和“核销通知（消费）”已具备可靠通知代码，等待部署后用真实沙箱订单完成最终验收。
- 部分按份数、按出行人的退订规则和携程测试用例。
- `RefundOrder` 仅退款：该接口只在合同约定由商家处理对客售后时接入；未确认前继续由 VBooking 人工处理。
- 当前订单采用同步确认模式（`supplierConfirmType=1`），不额外发送异步下单确认；若携程在遍历测试中要求异步确认，再按测试用例启用对应通知，避免重复确认。
- 真实闸机核销触发 `OrderConsumedNotice` 的沙箱和生产现场响应验收。
- 携程账单样本与本系统核销收入、取消和退款事实的对账验收。
- 生产账号、生产密钥和携程提供的正式来源网络地址。

以上项目在真实沙箱通过前不标记为生产可用，也不使用模拟成功代替。
