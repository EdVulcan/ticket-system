# 当前开发推进路线（2026-08-01）

本文是当前阶段的执行顺序，详细领域边界仍以
`platform-multitenancy-development-guide.md` 为准。系统坚持“帮助现场完成工作，
而不是用流程框死人”：租户、景区、票权、库存和金额事实保持硬边界；经授权的
纠错、争议和例外通过追加原因与审计完成，不覆盖原始事实。

## 1. 第一优先级：窗口收银闭环

当前批次：

- Wails POS 接入服务端班次汇总，开班允许录入备用金。
- 交班同时展示现金、微信、支付宝的实收、退款和净收，以及应交、实盘和差异。
- 现金收款保存应收、顾客实付和找零事实；实付不足时服务端拒绝且不留下支付记录。
- 管理端提供班次详情、主管复核和追加式实盘更正；原始关班金额不覆盖，每次更正要求原因并写审计。
- 窗口支持“现金部分 + 一种数字支付补足余款”；部分现金请求幂等、不会被未支付回收任务取消，数字支付失败可重试，放弃时必须退回现金并追加退款与审计事实。
- 组合支付售后退款按原现金与数字支付可退余额拆分；只有全部渠道退款确认后才统一释放票权、库存和结算事实，失败可重试并显示人工复核状态。
- 未配置打印机和证件阅读器继续 fail-closed，不以假成功替代现场联调。

下一批：

- 微信付款码收款在真实商户接口验证前不开放；微信/支付宝主扫和支付宝付款码进入真实商户联调。
- 用有效员工、设备和支付配置完成 Wails POS 全流程 E2E。

验收：开班 -> 售票 -> 现金找零/数字支付 -> 打印任务 -> 退款 -> 交班 -> 主管更正/复核全程可追溯，两个窗口互不串班。

## 2. 第二优先级：供应商与分销商

当前批次：

- 供应履约详情展示当前供应商拥有的游客快照、票权益、核销记录、相关售后和票级退款结算冲减；销售主单中其他供应商的明细不暴露。
- 结算工作台支持详情、生成、双方确认、争议、追加调整后重确认和付款凭证登记；调整保留原履约行和基础净额，不覆盖原始事实。
- 供应商和分销商可分别查看其管理或拥有的账户、预付余额、授信占用、冻结金额和不可变流水。

下一批：

- 用一个销售订单拆分两个供应商的完整场景做页面级责任验收，进一步优化按供应商、分销商和结算周期筛选。
- 补充结算导出和双方现场确认的对账格式；不扩展为通用会计、发票或企业财务系统。
- 争议纠错采用追加调整与操作日志，不直接修改既有履约或结算行。

验收：供应商授权 -> 分销销售 -> 景区履约/退款 -> 双方结算与争议调整能够由业务人员在页面完成。

## 3. 第三优先级：售后灵活性

当前批次：

- 改期、换票支持同一订单项内按游客/票权益部分处理；无法精确归属游客的聚合票保持拒绝。
- 差价补收、按原支付来源退差价和主管结算价例外审批进入统一售后事实；支付或退款未完成时状态明确可见。
- 主管可在受控设备和班次下代补打，记录原因、班次操作员和代处理人。
- 管理端按售后类型收敛表单，显示资金状态、退款分摊和完整事件时间线。

下一批：

- 用真实微信/支付宝商户完成换票补差与退差价联调。
- 通过管理端 Playwright 覆盖部分改期、部分换票、支付等待、退款等待和主管代补打。
- 已进入结算单的履约价差继续走争议与追加调整，不允许售后流程改写已确认结算行。

## 4. 第四优先级：旅行社团队

当前批次：

- 旅行社和景区供应商均可查看其业务关系内的团队、游客票权益、确认单、临时人数变更和分批入园记录；无关租户不能按 ID 猜测读取。
- 只有供应商租户的有效操作员、在线景区设备和检票点能够执行团队入园；每名游客必须关联该团队已支付订单中的供应商票权益，并写入统一核销事实。
- 分批入园请求使用幂等键，网络重试返回原批次；多批累计人数驱动团队完成状态，不重复核销。
- 旅行社可提交追加式团队确认单版本，快照保存确认人数、导游、车辆和现场说明；供应商可确认收到，双方历史不被覆盖。
- 已确认团队支持带原因的临时加减员。加员只有匹配到尚未分配的已支付票权时才可入园；减员若仍绑定有效票，必须先完成退票或作废。
- 团队结算支持生成、供应商确认、旅行社确认、争议、追加调整后重新确认和付款登记；原始金额不覆盖，付款后团队同步结清并写审计。
- 资金与对账页按旅行社/供应商关系汇总合同额度、合同额、预付款、授信占用、待结、争议和已付，仅服务上下游对账。

下一批：

- 结合景区现场制度完善团队售后与临时加单/补单，不允许名单变更直接制造票权。
- 增加可打印的正式确认单版式，以及旅行社和供应商双方可导出的结算对账格式。
- 使用旅行社、供应商、真实员工和真实闸机设备完成浏览器 E2E 与现场验收。
- 通用发票、企业财务系统、通用总账和付款审批不在当前范围。

验收：旅行社建团和绑定已支付订单 -> 提交确认单 -> 景区确认 -> 临时人数变更 -> 多批入园 -> 争议调整 -> 双方确认和付款，全程按角色可操作且可追溯。

## 5. 第五优先级：外部渠道

- 在拿到协议和凭据后实现智游宝、携程、美团适配器、渠道退款和可靠回调。
- 建设商品、订单、支付、退款、核销和账单对账工作台。
- 增加渠道联调工具、请求日志和受审计人工重放。
- 缺少真实协议或凭据时保持明确失败，不模拟厂商成功响应。

## 6. 第六优先级：自动化与生产验收

- 管理端 Playwright E2E 和 Wails POS 自动化交互测试。
- 平台、供应商、分销商、旅行社四种身份的完整浏览器流程。
- 使用实际部署目录完成 SQLite 备份恢复演练，并增加真实旧版本数据库样本。
- 容量、长时间稳定性、真实支付、打印/读卡/扫码和闸机现场验收。

平台小程序和 H5 商城继续暂缓，不计入当前阶段缺口。
