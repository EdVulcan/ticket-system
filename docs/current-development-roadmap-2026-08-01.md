# 当前开发推进路线（2026-08-01）

本文是当前阶段的执行顺序，详细领域边界仍以
`platform-multitenancy-development-guide.md` 为准。系统坚持“帮助现场完成工作，
而不是用流程框死人”：租户、景区、票权、库存和金额事实保持硬边界；经授权的
纠错、争议和例外通过追加原因与审计完成，不覆盖原始事实。

## 1. 第一优先级：窗口收银闭环

当前批次：

- Wails POS 接入服务端班次汇总，开班允许录入备用金。
- 交班同时展示现金、微信、支付宝的实收、退款和净收，以及应交、实盘和差异。
- 现金收款保存应收、顾客实付和找零事实；实付不足时服务端拒绝且不留下支付记录。
- 管理端提供班次详情、主管复核和追加式实盘更正；原始关班金额不覆盖，每次更正要求原因并写审计。
- 窗口支持“现金部分 + 一种数字支付补足余款”；部分现金请求幂等、不会被未支付回收任务取消，数字支付失败可重试，放弃时必须退回现金并追加退款与审计事实。
- 组合支付售后退款按原现金与数字支付可退余额拆分；只有全部渠道退款确认后才统一释放票权、库存和结算事实，失败可重试并显示人工复核状态。
- 未配置打印机和证件阅读器继续 fail-closed，不以假成功替代现场联调。

已记录待修复：

- 后台政策知识库与 Wails POS 的政策查询入口已经存在，但售票员查询接口当前仍会返回已停用政策；改为只展示启用政策，并补充“后台停用后窗口不可见、关键词查询可用”的桌面端自动化测试。

本轮完成：

- 修复政策停用字段无法写入的问题；售票员只查询启用政策，管理员仍可维护全部政策，并增加窗口关键词查询自动化。
- 新增闸机直连云端认证、nonce 防重放、限流、持久核销幂等和物理开闸结果记录。
- 新增轻量 `gate-client`，只有云端允许后才调用真实 HTTP 开闸驱动；驱动未配置或失败时明确回报失败。具体厂商协议和实物验收仍列入现场准入。
- 供应商可按票种配置闸机本地音频编号；编号随产品版本和售出票据固化，换票采用目标票种配置，分销销售继承供应商配置，已售门票不受后续修改影响。闸机程序只播放本机预置音频，核销时不生成或下载语音。
- 支付接入准备已增加渠道配置就绪检查、租户专属 HTTPS 回调校验和统一付款码入口；商户参数不完整时不能误启用，微信付款码在取得现场设备或收单协议前明确失败且不会取消待支付订单。

待真实条件：

- 微信付款码收款在真实商户接口验证前不开放；微信/支付宝主扫和支付宝付款码进入真实商户联调。
- Wails POS 已覆盖员工登录、备用金开班、分支付方式交班汇总、现金找零和打印未配置保留任务的自动交互；仍需用真实员工、设备和支付配置完成现场全流程验收。
- Wails POS 已按员工角色收敛工作区：售票员只进入售票/订单/班次，验票员只进入核销和终端配置；订单查询使用服务端真实状态并支持 10/20/40 分页。

验收：开班 -> 售票 -> 现金找零/数字支付 -> 打印任务 -> 退款 -> 交班 -> 主管更正/复核全程可追溯，两个窗口互不串班。

## 2. 第二优先级：供应商与分销商

当前批次：

- 供应履约详情展示当前供应商拥有的游客快照、票权益、核销记录、相关售后和票级退款结算冲减；销售主单中其他供应商的明细不暴露。
- 销售订单详情按供应商和履约景区分组展示票数、核销、退款冲减、佣金和应结净额；分销商只查看责任归属，不能操作供应商门票核销。
- 结算工作台支持详情、生成、双方确认、争议、追加调整后重确认和付款凭证登记；调整保留原履约行和基础净额，不覆盖原始事实。
- 结算详情可导出 Excel 直接打开的 UTF-8 CSV，包含结算快照、履约行和追加调整，不建设通用报表模板系统。
- 供应商和分销商可分别查看其管理或拥有的账户、预付余额、授信占用、冻结金额和不可变流水。
- 供应商给分销商充值按当前供应商拥有的分销关系解析账户，使用整数分和幂等键；其他租户的关系编号不能用于充值。
- 供应商按具体合作方维护产品结算价；旅行社合同由供应商创建和调整，合同产品价在同一事务中同步为该旅行社的供货价，旅行社不能自行定价，历史订单继续使用下单快照。
- 租户端履约、结算和渠道映射使用合作方、景区和产品名称选择，不要求业务人员手填租户或产品数据库编号。

待真实业务样本：

- 根据实际订单量补充按供应商、分销商和结算周期的必要筛选，不单独建设责任工作台。
- 用真实月度账单验证现有导出格式是否满足双方现场确认；不扩展为通用会计、发票或企业财务系统。
- 争议纠错采用追加调整与操作日志，不直接修改既有履约或结算行。

验收：供应商授权 -> 分销销售 -> 景区履约/退款 -> 双方结算与争议调整能够由业务人员在页面完成。

### 跨供应商组合产品（已完成代码闭环）

- 分销商在管理端选择已导入且仍有效的多个供应商产品，设置组合名称、销售端、总售价、组件数量和零售价分摊；系统要求至少两个不同供应商，分摊总额必须等于组合售价。
- 保存时创建不可变组合版本，快照供应商报价、来源产品版本、履约景区、结算单价和佣金。改版生成新版本并自动下架，确认后再上架，旧订单不受影响。
- Wails 窗口端将组合显示为一个商品并按一个总价收款；订单服务在同一 PostgreSQL 事务中逐组件扣供应商库存、配额和分销账户，生成供应商独立履约单、票码和票权益，任一组件失败则全部回滚。
- 组合没有跨景区通用票码。各组件只能由所属供应商在所属景区核销；未使用组件按其分摊金额独立退款并冲回对应供应商资金、库存、配额和结算。
- 任一供应商合作、报价、结算价、销售期或产品版本变化都会阻止组合继续新售，已售票仍使用下单快照。外部渠道组合映射没有真实协议时保持明确拒绝。

## 3. 第三优先级：售后灵活性

当前批次：

- 改期、换票支持同一订单项内按游客/票权益部分处理；无法精确归属游客的聚合票保持拒绝。
- 差价补收、按原支付来源退差价和主管结算价例外审批进入统一售后事实；支付或退款未完成时状态明确可见。
- 主管可在受控设备和班次下代补打，记录原因、班次操作员和代处理人。
- 管理端按售后类型收敛表单，显示资金状态、退款分摊和完整事件时间线。

待真实支付条件：

- 用真实微信/支付宝商户完成换票补差与退差价联调。
- 通过管理端 Playwright 覆盖部分改期、部分换票、支付等待、退款等待和主管代补打。
- 已进入结算单的履约价差继续走争议与追加调整，不允许售后流程改写已确认结算行。

## 4. 第四优先级：旅行社团队

当前批次：

- 旅行社和景区供应商均可查看其业务关系内的团队、游客票权益、确认单、临时人数变更和分批入园记录；无关租户不能按 ID 猜测读取。
- 只有供应商租户的有效操作员、在线景区设备和检票点能够执行团队入园；每名游客必须关联该团队已支付订单中的供应商票权益，并写入统一核销事实。
- 分批入园请求使用幂等键，网络重试返回原批次；多批累计人数驱动团队完成状态，不重复核销。
- 旅行社可提交追加式团队确认单版本，快照保存确认人数、导游、车辆和现场说明；供应商可确认收到，双方历史不被覆盖。
- 已确认团队支持带原因的临时加减员。加员只有匹配到尚未分配的已支付票权时才可入园；减员若仍绑定有效票，必须先完成退票或作废。
- 团队结算支持生成、供应商确认、旅行社确认、争议、追加调整后重新确认和付款登记；原始金额不覆盖，付款后团队同步结清并写审计。
- 团队确认单可按提交版本打印，打印内容只使用该版本已保存的确认人数、导游、车辆和现场说明，并明确不把当前游客名单冒充为历史快照。
- 团队结算可由旅行社或供应商导出 UTF-8 CSV 对账单；旅行社可从团队详情按绑定订单进入统一售后工作台，查询及发起现有票级售后。
- 资金与对账页按旅行社/供应商关系汇总合同额度、合同额、预付款、授信占用、待结、争议和已付，仅服务上下游对账。
- 旅行社合同页面由供应商直接选择合作旅行社和产品维护专属结算价；创建团队从有效合同选择供应商和景区，绑定订单只列出日期、供应商和景区匹配的已支付订单。

待现场制度与设备：

- 结合景区现场制度完善团队售后与临时加单/补单，不允许名单变更直接制造票权。
- 待现场确认确认单签章、页眉和纸张要求；在此之前保留当前简洁打印版式，不建设模板设计器。
- 使用旅行社、供应商、真实员工和真实闸机设备完成浏览器 E2E 与现场验收。
- 通用发票、企业财务系统、通用总账和付款审批不在当前范围。

验收：旅行社建团和绑定已支付订单 -> 提交确认单 -> 景区确认 -> 临时人数变更 -> 多批入园 -> 争议调整 -> 双方确认和付款，全程按角色可操作且可追溯。

## 5. 第五优先级：外部渠道

当前批次：

- 管理端支持独立下游渠道账号、权限、IP 白名单、限流、密钥轮换和商品映射。
- 渠道请求日志展示请求 ID、接口、来源 IP、响应码、尝试次数和响应摘要；确定的 `4xx` 结果幂等重放，`5xx` 进入失败待处理。
- 管理员可写明原因授权失败请求重试；渠道方必须使用相同请求 ID 和相同正文重发，后台不冒充渠道构造签名请求。
- 渠道账单支持批次导入、逐笔匹配内部订单/支付/退款、差异下钻和渠道账号内幂等；不同渠道账号可使用相同批次号。

已完成补充：

- 管理端已增加渠道订单综合查询，可按内部/外部单号、游客姓名或手机号查询，并下钻票、支付退款、核销和售后事实；查询严格限定租户和渠道账号。

待真实渠道条件：

- 在取得真实协议和凭据后实现携程、美团等下游销售渠道适配器、渠道退款和可靠回调。
- 按真实厂商协议增加联调工具和回调投递记录，不预设厂商状态机。
- 缺少真实协议或凭据时保持明确失败，不模拟厂商成功响应。
- 智游宝目前只视为潜在上游供应系统，不作为下游销售渠道；上游接入当前暂缓。

## 6. 第六优先级：自动化与生产验收

- 管理端 Playwright 已同时具备前端烟雾测试和真实后端测试，并在 CI 独立运行；真实测试每次构建 Go 服务、创建隔离的临时 SQLite，通过公开平台 API 初始化租户，不接触现有业务库。
- 平台、景区供应商、纯分销商、旅行社四种身份已覆盖真实登录、菜单与路由边界；团队工作区只允许供应商或旅行社能力进入。
- Wails POS 渲染层核心交互和 Go 硬件桥 fail-closed 已纳入 Playwright/Go 自动化并接入 CI；真实支付与硬件不以模拟通过代替。
- PostgreSQL 自定义格式备份、配套密钥、恢复校验和回滚 dump 已完成真实集成测试；实际部署目录恢复演练等待部署现场，旧版 SQLite 样本仅在以后明确要求导入旧数据时提供。
- 容量、长时间稳定性、真实支付、打印/读卡/扫码和闸机现场验收按[现场联调准备清单](./field-integration-readiness-checklist.md)执行。

平台小程序和 H5 商城继续暂缓，不计入当前阶段缺口。
