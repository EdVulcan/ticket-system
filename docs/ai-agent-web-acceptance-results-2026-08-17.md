## 结论

本轮不能判定 AI Agent 全量验收通过。预览确认、租户内范围解析、只读报表和部分移动端体验已有可用路径，但目录创建、检票点/规则组操作、复合查询和若干边界提示存在失败；角色隔离、断网/超时/并发确认等用例还缺少测试前置或浏览器能力。

本轮没有未经确认的领域写入。唯一获授权的低风险写入是沙盒票售价 `1.00 -> 1.01 -> 1.00`，页面和任务终态均复核为原值。

## 2026-08-18 代码修复与自动化复核

本节追加记录修复，不改写上面的真实 Web 失败证据：

- 新建票种补充信息、检票点/规则组请求的服务端路由已按持久任务原始意图收敛；补充景区、票价和检票点时不会再因为“最多/检票点”词汇误判为票规调整。
- 原生工具运行时现在只接受当前任务实际暴露的工具；单工具任务在兼容模型上强制选择唯一工具，推理模型保留自动选择兼容路径。创建票种、规则组续谈和复合只读不会再因 Provider 自行选择未暴露工具而越过任务路由。
- Agent 任务幂等键和服务层读取统一为 `(tenant_id, actor_user_id, idempotency_key)`；数据库 schema 升级到 101，并用 PostgreSQL 原子冲突重读覆盖并发创建。显式指定其他租户会在创建任务和 Provider 调用前拒绝。
- 同一任务的 Provider 规划回合增加持久 planning 单飞锁；并发回合不会重复调用 Provider，超过租约的遗留 running 事件会先失效再允许恢复。
- 复合只读查询增加 `query_compound_readonly` 服务端白名单适配器，支持 2-5 个只读步骤；“先查询/依次查询/查询多个主题”等自然表达可路由到该工具，混入写入词不会被当成只读复合任务。
- 支付、退款、设备、凭据、分销授权、上架和权限等未开放能力返回明确边界提示；前端任务指针改为标签页 `sessionStorage`，创建幂等键与本标签页最近一次提交文本绑定，内容改变时自动使用新键。
- 自动化验证：`go test ./...` 通过；管理端 `npm run build` 通过；`git diff --check` 通过。`go test -race ./internal/service` 在当前 Windows 环境因未安装 C 编译器（`gcc not found`）无法启动，不能宣称竞态测试通过。

修复后的真实 Web 重跑尚未完成：当前 in-app Browser 会话对部分子 Agent 返回 `Browser is not available`，因此上方 W1-W4 的失败/阻塞记录仍然有效，不能把代码级回归替代 Web 验收。下一轮应在可用浏览器会话中重跑 B-04/B-05、D-01/D-03、F-03/F-06、G-04、H-03/H-04，并使用两个租户/操作者和两个标签页核对任务隔离。

## 必须进入缺陷跟踪的问题

1. **P1：补齐信息后的新建票种路由错误。** 线上票和窗口/POS 票在补充景区、检票点后稳定被解释为票规调整，未生成票种预览。两类创建均未写入。
2. **P1：检票点和规则组没有可信 Agent 工具路由。** 检票点请求提示未调用受支持工具；规则组请求错误进入新票种信息收集。两者均未生成预览。
3. **P1：跨租户意图未明确拒绝。** 输入包含 `SYS002` 时，UI 降级为当前 `SYS001` 的本地票种消歧。没有跨租户泄露或写入，但用户会被误导继续操作错误范围；服务端应把显式外部租户限定转成拒绝或无候选。
4. **P1：复合只读请求不稳定。** 四步订单/库存/销售/核销查询未调用受支持查询工具，无法生成可信结果。
5. **P1：共享浏览器上下文出现 Agent 幂等键冲突。** W2 记录 `idempotency key already belongs to another agent task`；主线程全新会话复测库存成功，因此尚不能断言所有新任务必现，但必须补跨标签/并行会话回归测试并验证任务键不会被复用或串任务。
6. **P1：不支持/高风险请求的用户提示过于泛化。** 分销、酒店凭据、支付退款、设备控制和混合退款请求都能 fail-closed，但只显示“未调用受支持工具”，没有告诉用户当前明确不开放的能力。
7. **P1：长文本任务可能长期 loading。** W3 的 985 字符 HTML/脚本文本未执行脚本、无横向溢出，但提交后超过 53 秒仍禁用输入且无超时/失败反馈。
