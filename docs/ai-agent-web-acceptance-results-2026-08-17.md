## 结论

本轮不能判定 AI Agent 全量验收通过。预览确认、租户内范围解析、只读报表和部分移动端体验已有可用路径，但目录创建、检票点/规则组操作、复合查询和若干边界提示存在失败；角色隔离、断网/超时/并发确认等用例还缺少测试前置或浏览器能力。

## 2026-08-18 代码修复与自动化复核

本节追加记录修复，不改写上面的真实 Web 失败证据：

- 新建票种补充信息、检票点/规则组请求的服务端路由已按持久任务原始意图收敛；补充景区、票价和检票点时不会再因为“最多/检票点”词汇误判为票规调整。
- 原生工具运行时现在只接受当前任务实际暴露的工具；单工具任务在兼容模型上强制选择唯一工具，推理模型保留自动选择兼容路径。创建票种、规则组续谈和复合只读不会再因 Provider 自行选择未暴露工具而越过任务路由。
- Agent 任务幂等键和服务层读取统一为 `(tenant_id, actor_user_id, idempotency_key)`；数据库 schema 升级到 101，并用 PostgreSQL 原子冲突重读覆盖并发创建。显式指定其他租户会在创建任务和 Provider 调用前拒绝。
- 同一任务的 Provider 规划回合增加持久 planning 单飞锁；并发回合不会重复调用 Provider，超过租约的遗留 running 事件会先失效再允许恢复。
- 复合只读查询增加 `query_compound_readonly` 服务端白名单适配器，支持 2-5 个只读步骤；“先查询/依次查询/查询多个主题”等自然表达可路由到该工具，混入写入词不会被当成只读复合任务。
- 支付、退款、设备、凭据、分销授权、上架和权限等未开放能力返回明确边界提示；前端任务指针改为标签页 `sessionStorage`，创建幂等键与本标签页最近一次提交文本绑定，内容改变时自动使用新键。

4. **P1：复合只读请求不稳定。** 四步订单/库存/销售/核销查询未调用受支持查询工具，无法生成可信结果。

## 2026-08-18 报表单项查询路由修复

部署前线上复测发现，“查询最近 30 天的核销汇总”仍被模型返回的普通文本打回泛化错误，而服务端其实已经能按租户和权限确定唯一的核销汇总适配器。根因是“核销汇总”被词法策略误判为票规变更，且单项报表仍把最终工具选择交给模型。

- “查询/查看/统计”且没有变更动词的请求不再被当成检票规则变更；“查询核销汇总”“查看检票点”“查询核销规则”保持只读路径。
- 销售汇总和核销汇总在服务端唯一匹配后直接调用只读适配器，保留租户过滤、权限校验、QueryResult 持久化和工具审计；目录、订单、库存、复合查询及所有预览/写入仍使用原生工具协议。
- 显式 `YYYY-MM-DD` 日期范围会传给报表适配器；未提供日期时沿用最近 30 天默认范围。该直连路径不执行任何领域写入，也不绕过 AI 助手权限。

本地针对性回归和完整 `go test ./...` 均通过，管理端构建和 `git diff --check` 通过。代码发布后必须重新执行销售汇总、核销汇总和四步复合查询线上用例；在部署复测完成前，不把线上报表验收标记为通过。

## 2026-08-18 复合只读请求确定性路由修复

针对四步“最近订单、线上库存、销售汇总、核销汇总”仍依赖模型选择工具而返回空计划的问题，服务端现在会对明确的多主题只读请求按用户提及顺序解析 2 到 5 个已注册查询适配器，再统一经过原有白名单、租户、权限和参数校验。日期范围只传给支持日期过滤的适配器；查询结果仍以服务器 `QueryResult` 事实包持久化，未增加任何写入能力。票种规则/授权商品等更具体主题不会被“票种/商品”通用词重复拆成两个查询。

新增并通过本地回归：四步订单/库存/销售/核销请求不再调用 Provider，结果持久化为 4 个查询事实；用户顺序和具体主题去重均有测试；混入退款等写入意图仍 fail-closed。线上 Web 复测需要等待本次部署完成；浏览器控制器当前不可用，尚未把本地回归替代线上验收。

补充修复：只读请求中常见的安全限定语（例如“只读，不执行任何修改、支付或外部调用”）不再因包含被禁止能力词而误拒绝；肯定式退款/支付请求仍在服务端入口 fail-closed。该限定语及肯定式退款均有回归测试。

## 2026-08-18 核销汇总安全限定语回归修复

线上复测继续发现“查询最近 30 天的核销汇总；只读查询，不执行任何修改”仍可能被票规词法守卫误判为写入请求。根因是该守卫对“修改”使用了原始词法匹配，没有识别其位于“不执行”否定范围内。

- 票规变更守卫现在与只读/不支持能力策略共用肯定式词法判断；安全限定语中的“修改、支付、外部调用”等词不会改变核销汇总的只读路由。
- 新增回归用例覆盖带“只读查询，不执行任何修改”的核销汇总请求；肯定式退款仍保持 fail-closed。
- `CGO_ENABLED=1 GOTOOLCHAIN=local go test ./... -count=1`、定向服务测试、`go vet ./internal/service` 和 `git diff --check` 通过。
- 本机 `go test -race` 仍因未安装 GCC 无法启动（`cgo: C compiler "gcc" not found`），不能据此宣称竞态测试通过；应在 CI/具备 C 编译器的环境补跑。
