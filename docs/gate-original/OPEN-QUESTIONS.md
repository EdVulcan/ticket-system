1. `0x142/0x152` 的完整 payload、方向和控制板响应是什么？（先确认它们是否属于当前 P07=6 路径。）
2. `setPoleUpDown` 参数值对应什么动作，是否有脉冲宽度或方向限制？
3. 哪个反馈代表“收到业务命令”，哪个反馈代表“杆已完成转动”？
4. `C6/C8/CC/E2/E4`、`0x14/0x15/0x71/0x73/0x74` 的厂商业务名称和状态机是什么？
5. 断电、超时、尾随和人工放行时控制板反馈如何表达？

## P1：影响稳定共存

1. `/etc/init.d/rcS` 的真实启动顺序以及 `S98-ticket-gate` 与 `start_a9.sh` 的先后。
2. `start_a9.sh` 的 `ps | grep "ticket"` 在现场实际输出中是否会命中 `ticket-gate`。
3. `/dev/urandom` 权限在重启后由哪个脚本/设备初始化恢复，是否能在不改原厂程序的前提下稳定修正。
4. 原厂 watchdog 的实际超时、喂狗状态和复位日志。
5. P93 条码波特率枚举 `1` 的真实波特率及扫码器帧结束符。

## 安全验证顺序

1. 先拿厂商协议或控制板台架，确认完整字段和反馈方向。
2. 已完成现有样本的离线结构 parser fixture；后续如取得 commKey/厂商样本，再扩展为离线解密和字段状态机测试。
3. 事件处理函数已静态定位；下一步只在隔离台架验证“发送 → 控制板反馈 → 杆动作”，记录 `opened/failed/unknown`。
4. 现场仅做被动监听和对照样本；未经批准不得注入 CAN。
5. 单通道低峰切换，保留原厂回退；任何未知物理结果都锁定并要求现场确认。

## 完成定义

只有同时满足以下条件，才允许进入真实三辊闸驱动实现：

- 控制板协议字段和动作参数有 A/B 级证据；
- 业务 ACK 与物理杆完成信号可区分；
- 有效、重复、过期、退款、跨景区、断网和超时 fixture 通过；
- 断电和恢复不会重复核销或二次开闸；
- 原厂共存与回退路径已在隔离环境验证；
- gate-client 仍不抢占扫码串口，硬件结果始终独立持久化。
