# 平台 AI 助手

> **Phase 5（2026-08-16，进行中）**：在不开放高风险执行的前提下，增加租户业务别名、Provider 瞬态失败保护、provider-independent 评测回归和 2-5 步低风险复合预览。别名只解析当前租户现有景区、检票点和自有票种；Provider 仅对网络、429 和 5xx 做一次受控重试，连续失败会短暂熔断，401/其他 4xx 不重试。

> **Phase 4（2026-08-16）**：新增批量修改未上架、未分销票种基础信息的预览/确认操作。一次至少两个、最多 50 个精确票种名称，共享一组基础字段；统一改名、检票规则、上架、分销、渠道、库存预占和资金事实仍不开放。

平台 AI 助手是管理端的受限操作入口。它把自然语言转换成后端已定义的查询工具或预览计划，再复用现有领域服务的预览、锁定、revision 和审计流程。运行时使用独立的、版本化的领域 Skill（不是开发 Agent 的 `.codex` Skill）；服务端通过 `agentModuleManifest` 按任务类型加载系统知识契约和模块 Skill，并把 Knowledge Pack ID、版本和哈希保存到任务上下文。Skill 资源位于 `backend/internal/service/skills/`，通过 Go embed 随服务端发布，租户不能修改。任务续聊会继续使用创建时的 Knowledge Pack；部署后知识包发生变化时，旧任务会要求新建任务，不会静默改变规划规则。

系统知识契约位于 `skills/agent_system.md`，描述平台实体关系、模块当前开放等级、查询/预览/确认边界和后续模块接入标准。工具注册表的每个工具还声明所属模块、动作等级、权限、租户能力、供应商业态和确认要求。新增业务模块必须先增加 Manifest 和知识包，再增加只读或预览工具；模型不能直接调用确认或执行工具。

## 管理员配置

平台管理员登录平台管理中心后，打开“AI 助手配置”：

- 选择 `DeepSeek` 或 OpenAI 兼容接口，填写 HTTPS 接口地址和模型名称。
- 填写 API Key。保存后只显示“已配置”，不会回显原文；留空保存会保留已有密钥。
- 选择后台助手协议：`tool_v1` 使用 provider 原生函数调用；`auto` 对 DeepSeek 默认使用 `tool_v1`，其他兼容接口仍使用旧协议；`legacy_json` 只用于明确需要兼容旧任务的接口。新建配置默认是 `auto`，schema 94 会把旧的 DeepSeek 默认 `legacy_json` 配置迁移为 `auto`。协议在新任务创建时固定，已存在任务不会中途切换。
- 设置每个租户的月度请求数、月度 Token 数、请求超时、输出额度和温度。请求超时默认 120 秒，最长 120 秒；浏览器会额外保留响应缓冲时间。输出额度为 `0` 时表示自动模式：请求不携带 `max_tokens`，由模型或兼容接口使用自己的默认额度；只有填写正数时才会设置单次上限。月度 Token 额度仍会用保守估算预留，并在成功响应后按 provider 实际用量冲正，这不是单次输出上限。
- DeepSeek 的旧 `legacy_json` 规划请求会显式启用 JSON Output（`response_format.type=json_object`）；原生 `tool_v1` 请求使用受限函数工具，不把普通自然语言当作计划。两条路径都由服务端执行字段白名单、租户候选对象解析和业务规则校验；其他 OpenAI 兼容接口必须自行支持其选择的协议，不能依赖模型输出自然语言后由系统猜测。
- 先点“测试连接”，确认接口可用后再启用。连接探测会按当前选择的协议执行：`legacy_json` 使用 provider 默认输出预算，`tool_v1`/DeepSeek `auto` 会要求 provider 返回一次受限探针工具调用；不会用过小的 token 上限误判模型。Provider 返回 401、模型不存在、未实现函数调用或限流时会明确提示，不能把普通文本响应当作工具计划。未配置、停用、解密失败或接口地址不满足 HTTPS 要求时，租户侧请求会明确失败。
- 如果模型是 `deepseek-reasoner` 或其他推理模型，系统仍要求最终响应包含可解析的 JSON；只有 `reasoning_content` 或因 `finish_reason=length` 没有最终 `content` 时，系统会拒绝生成计划，不会把内部推理文本当作可执行计划。可以先使用自动模式，只有需要控制单次成本时才填写正数上限。

系统只保存平台级连接配置，当前不接受租户自带 API Key。每个租户的请求数和 Token 数按 `YYYY-MM` 写入独立用量账本； provider 失败后的已预留请求仍会计入，避免重试风暴绕过额度。未来做租户付费套餐时，应在此账本上增加套餐额度和计费事实。

## 租户使用

具备租户 `agent.use` 权限的账号，会在管理端看到右下角悬浮 AI 助手。工具本身仍按岗位权限、租户能力和供应商业务类型过滤：

1. 输入自然语言。可以描述票规变更，也可以描述新票种，例如“创建一个线上成人票，售价 120 元，结算价 80 元，使用北门检票点”。
2. 助手会在同一任务中持续收集缺失信息。售价、结算价、所属景区或检票点规则不完整时，只返回问题，不生成产品，也不写入半成品记录。
3. 线上票和窗口/POS 票是不同的 `product_type`：`online` 表示线上票，`offline` 表示窗口/POS 票。未明确类型时助手必须追问，不能默认。批量操作使用“所有飞车套票”这类表达时，只覆盖名称中明确匹配该类别的当前租户票种；只有明确说“所有票种/全部门票”才是全量范围。新增检票点若票种包含多个规则组，助手会先询问规则组，用户可以直接点击或回复组名继续。信息完整后检查预览。批量票规预览包含每个票种的变更前/后规则、revision、影响授权和阻断原因；新票种预览包含完整产品/规则字段，并明确显示票种类型，同时固定为“未上架”、不可分销、不创建渠道映射。
4. 明确确认后才执行。批量规则仍由原计划哈希和产品锁保护；新票种在同一个任务事务中调用现有产品创建服务。重复确认返回同一结果，过期或当前数据变化会拒绝执行。
5. 任务过期、冲突或输入方向改变时，可以点击“新建任务”。系统会把当前规划任务标记为 `cancelled` 并保留审计记录，不删除历史上下文；正在执行的任务不能被放弃，避免把已开始的业务操作误认为已取消。

`tool_v1` 当前注册的查询工具包括目录、`search_orders`、`query_ticket_inventory`、`query_sales_summary` 和 `query_verification_summary`；预览工具包括 `prepare_ticket_product_create`、`prepare_ticket_product_update`、`prepare_ticket_product_batch_update`、`prepare_compound_preview` 和 `prepare_catalog_rule_change`。其中单票种和批量票种修改都仅接受当前租户仍未上架、未分销票种的基础字段，确认时锁定当前产品版本并生成新版本；批量操作要求至少两个精确票种名称，统一改名仍关闭，检票规则继续使用批量票规预览。`prepare_compound_preview` 只编排 2-5 个既有低风险预览步骤，确认后按顺序执行，步骤之间不是跨域原子事务；中途失败时不重复已完成步骤。查询工具返回带模块、筛选条件、生成时间和数量信息的服务器 `QueryResult`，不返回数据库编号，也不执行写入。销售汇总按原收款期重述后续退款，核销汇总按首次有效核销日期计算。酒店、分销和渠道状态尚未注册工具，后续仍按同一注册表增加低风险能力。

租户可以在“AI 业务别名”页面维护景区、检票点和自有票种的常用叫法。别名保存时必须指向当前租户唯一存在的业务名称；解析时会再次校验目标，目标删除、重名或跨租户时 fail-closed。别名只改变输入解析，不改变权限、对象归属或实际业务名称。

悬浮助手没有直接写商品、票规、库存、分销授权或订单的权限。模型返回非法 JSON、未知工具、未知参数、跨租户对象或不支持的操作时，服务端拒绝生成预览，不会猜测执行。任务状态和规范化上下文持久保存在 `AgentTask`，模型请求和工具调用的脱敏结果、token 用量、调用编号和耗时追加写入 `AgentTaskEvent`；工具幂等键绑定任务版本、工具和参数，失败调用不会伪装成成功。批量领域计划已提交但任务收尾中断时，后续确认会依据计划状态恢复或标记失败，不会重复执行。刷新页面后可继续未完成任务，任务按租户和操作者隔离并有过期时间。

## 安全策略

模型只是不可信的计划建议器，不是权限边界，也不是通用聊天入口：

- 规划信封只允许已注册的票规调整、票种创建、单票种基础信息修改和批量票种基础信息修改；未知字段、伪造数据库编号、混合两种业务或任意文字回复都会被拒绝。
- 工具注册表是静态、版本化的 allowlist。工具展示前和调用时都会检查 `agent.use` 之外的领域权限、租户能力和业务类型；工具参数不能携带租户/用户/权限、SQL、URL、执行开关或服务端归属字段。
- 批量操作只允许 `add_checkpoints`、`remove_checkpoints`、`set_checkpoint_limit`。模型不能自行扩大到全部票种；只有用户明确写出“所有/全部票种或门票”时，服务端才接受全量范围。“所有某类票种”仍须逐个返回候选清单中的精确名称。用户明确要求新增规则组时，服务端使用 `create_group=true`，并在缺少 `group_name` 时进入补充信息状态；`group_max_total_check_in` 只有用户明确给出新组通行数量时才采用。普通多规则组票种的新增检票点仍须等用户补充现有 `group_name`，服务端不会猜测。
- 服务端会检查模型提出的增加、移除、设置方向是否与用户输入存在明显冲突，并重新按当前租户、景区和业务名称解析对象。模型不能通过提示词修改租户、供应商、渠道、状态或分销字段。
- 新票种预览展示所有将写入的业务字段，包括线上/窗口票种类型、未上架状态、不可分销、有效期、库存、实名/限购、退款、出票方式、标签、闸机语音和检票规则；预览只使用业务名称，不下发内部归属 ID。
- 租户目录名称和任务上下文在发送给 provider 时被标记为纯数据，不被当作指令；provider 的原始回复不会直接展示或执行。

因此，要求“忽略规则、执行 SQL、泄露密钥”不会获得任意执行路径；无关问题也不会被当作普通问答返回。但模型仍可能提出一个格式合法、业务上不符合操作者真实意图的计划，操作者必须核对影响票种和全部预览字段后再确认。正式开放给低信任用户前，还应继续增加提示词注入、全量操作和权限变更期间的浏览器回归测试。

## 数据和审计边界

- 发送给 provider 的上下文只包括当前租户的候选票种、检票点和景区名称以及本次任务上下文，不包括其他租户的商品、订单、数据库 ID、支付密钥或渠道凭证。
- 平台 API Key 使用系统加密密钥保存，永不通过租户接口返回，也不写入浏览器 `localStorage`。
- AI 请求、任务预览和最终确认分别受平台/租户权限保护；最终业务变化仍由既有批量/产品服务写入租户审计，任务确认本身也保留审计事实。
- AI 不是小红书、携程、支付或退款适配器。涉及资金、渠道、酒店履约或外部平台状态的业务，仍必须走对应的领域服务和 fail-closed 外部准入流程。
- 当前明确不注册支付、退款、结算、资金、渠道密钥、用户/角色/权限、设备/闸机人工核验、外部平台状态变更、SQL/HTTP/代码执行和自动上线/自动分发工具。增加新领域工具必须先定义权限、租户边界、预览语义和独立回归测试。
- Provider 评测使用固定的无密钥回放用例覆盖纯文本、未知字段、混合计划、数据库编号注入和无关请求；它验证服务端拒绝路径，不把一次模型成功响应当作上线证明。
