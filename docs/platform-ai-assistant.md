# 平台 AI 助手

平台 AI 助手是管理端的受限操作入口，当前支持景区供应商的批量票规部署和新票种创建。它把自然语言转换成后端已定义的操作 DSL 或产品创建计划，再复用现有领域服务的预览、锁定、revision 和审计流程。

## 管理员配置

平台管理员登录平台管理中心后，打开“AI 助手配置”：

- 选择 `DeepSeek` 或 OpenAI 兼容接口，填写 HTTPS 接口地址和模型名称。
- 填写 API Key。保存后只显示“已配置”，不会回显原文；留空保存会保留已有密钥。
- 设置每个租户的月度请求数、月度 Token 数、请求超时、最大输出 Token 和温度。
- 先点“测试连接”，确认接口可用后再启用。未配置、停用、解密失败或接口地址不满足 HTTPS 要求时，租户侧请求会明确失败。

系统只保存平台级连接配置，当前不接受租户自带 API Key。每个租户的请求数和 Token 数按 `YYYY-MM` 写入独立用量账本； provider 失败后的已预留请求仍会计入，避免重试风暴绕过额度。未来做租户付费套餐时，应在此账本上增加套餐额度和计费事实。

## 租户使用

具备景区供应商能力和 `catalog.write` 权限的账号，会在管理端看到右下角悬浮 AI 助手：

1. 输入自然语言。可以描述票规变更，也可以描述新票种，例如“创建成人票，售价 120 元，结算价 80 元，使用北门检票点”。
2. 助手会在同一任务中持续收集缺失信息。售价、结算价、所属景区或检票点规则不完整时，只返回问题，不生成产品，也不写入半成品记录。
3. 信息完整后检查预览。批量票规预览包含每个票种的变更前/后规则、revision、影响授权和阻断原因；新票种预览包含完整产品/规则字段，并明确固定为 `offline`、不可分销、不创建渠道映射。
4. 明确确认后才执行。批量规则仍由原计划哈希和产品锁保护；新票种在同一个任务事务中调用现有产品创建服务。重复确认返回同一结果，过期或当前数据变化会拒绝执行。

悬浮助手没有直接写商品、票规、库存、分销授权或订单的权限。模型返回非法 JSON、未知名称、跨租户对象或不支持的操作时，服务端拒绝生成预览，不会猜测执行。任务状态和规范化上下文持久保存在 `AgentTask`，刷新页面后可继续未完成任务；任务按租户和操作者隔离并有过期时间。

## 安全策略

模型只是不可信的计划建议器，不是权限边界，也不是通用聊天入口：

- 规划信封只允许 `catalog_batch_change` 和 `ticket_product_create` 两种业务类型；未知字段、伪造数据库编号、混合两种业务或任意文字回复都会被拒绝。
- 批量操作只允许 `add_checkpoints`、`remove_checkpoints`、`set_checkpoint_limit`。模型不能自行扩大到全部票种；只有用户明确写出“所有/全部票种或门票”时，服务端才接受全量范围。
- 服务端会检查模型提出的增加、移除、设置方向是否与用户输入存在明显冲突，并重新按当前租户、景区和业务名称解析对象。模型不能通过提示词修改租户、供应商、渠道、状态或分销字段。
- 新票种预览展示所有将写入的业务字段，包括有效期、库存、实名/限购、退款、出票方式、标签、闸机语音和检票规则；预览只使用业务名称，不下发内部归属 ID。
- 租户目录名称和任务上下文在发送给 provider 时被标记为纯数据，不被当作指令；provider 的原始回复不会直接展示或执行。

因此，要求“忽略规则、执行 SQL、泄露密钥”不会获得任意执行路径；无关问题也不会被当作普通问答返回。但模型仍可能提出一个格式合法、业务上不符合操作者真实意图的计划，操作者必须核对影响票种和全部预览字段后再确认。正式开放给低信任用户前，还应继续增加提示词注入、全量操作和权限变更期间的浏览器回归测试。

## 数据和审计边界

- 发送给 provider 的上下文只包括当前租户的候选票种、检票点和景区名称以及本次任务上下文，不包括其他租户的商品、订单、数据库 ID、支付密钥或渠道凭证。
- 平台 API Key 使用系统加密密钥保存，永不通过租户接口返回，也不写入浏览器 `localStorage`。
- AI 请求、任务预览和最终确认分别受平台/租户权限保护；最终业务变化仍由既有批量/产品服务写入租户审计，任务确认本身也保留审计事实。
- AI 不是小红书、携程、支付或退款适配器。涉及资金、渠道、酒店履约或外部平台状态的业务，仍必须走对应的领域服务和 fail-closed 外部准入流程。
