## 1. 过渡目标

合作景区旧区域继续使用智游宝的既有设备，新区域使用本系统的设备和检票点。对于明确配置为外部供票的产品，游客取得一份由智游宝签发的固定核销码；旧区域和新区域均可读取同一核销码，但各自只执行自身已配置的检票点与票权益规则。

这不是把智游宝的检票点、票规或订单状态复制进本系统，也不是把本系统作为智游宝的下游渠道。现有多租户、供应履约、票权益、退款和结算规则继续以开发基线为准。

## 3. 已确认的业务规则

### 3.1 产品和出票方式

1. 产品**默认**由本系统生成核销码。
2. 只有产品明确开启上游供应、选择具体供应连接，并配置对应的上游商品后，才向该上游系统出票并复用其实际核销码。
3. 已开启但配置不完整、上游出票失败或尚未取得完整核销码时，订单进入明确的待处理/失败路径；不得静默回退为本地出码。
4. 订单必须固化销售时的供应方式、供应连接、上游商品、双方订单身份、数量、游玩日期、外部票码和请求/响应快照。以后关闭、替换供应商或修改商品映射，只影响新订单，不改写已售票。

### 3.2 同码核销和展示

- 同一外部核销码可被本系统关联为本地票权益的核销入口。智游宝旧区域与本系统新区域分别维护自己的检票点、次数和剩余权益；任一侧的使用不能凭空扣减另一侧权益。
- 多张票可能统一关联同一个上游码，不强行虚构逐票外部映射；但本地订单数量和本地核销次数仍必须按已售快照准确处理。
- 任一区域已经使用后，订单对外可显示“已使用”，但二维码应继续显示，使其他区域在其剩余权益内仍可核销。两边都使用过后是否还能通行，仍由各自剩余次数决定。
- 本系统发生退款占用时暂停展示并阻止本地核销；退款成功后关闭展示并使本地票权失效。对于外部供票，还必须完成或确认上游失效，不能把隐藏页面二维码当作已撤销外部票权。

### 3.3 退款和重试

- 对外仍按整单处理：任一区域已使用即阻止普通整单退款；未使用的退票申请由系统自动审核通过，已使用自动拒绝。
- 上游退票首次响应不是最终完成事实。必须等待上游查询/确认结果后，才完成本地原路退款和票权、库存、资金事实的既有处理。
- 下单请求一旦发送，即保存不变的请求内容。响应超时后只查询原单；重复订单号被拒绝不代表原单失败，不能换一个订单号再次出票。

## 4. 实现方向

后续应以独立的上游供应适配器和采购履约模型承接 XML 协议，转换到现有统一订单、票权益、退款、库存和事件模型。外部字段不得反向成为核心订单的唯一事实，也不得复用下游渠道适配器来实现上游采购。

### 4.1 本地基础预置（2026-09-10，待发布）
